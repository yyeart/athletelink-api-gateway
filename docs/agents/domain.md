# Domain docs

Layout: single-context.

Before exploring the codebase, read the root CONTEXT.md
and relevant decisions in docs/adr/.

If these files are absent, proceed silently. Domain documents
and ADRs are created when terminology or decisions are resolved.

Use domain terms defined in CONTEXT.md. If a needed term is
missing, note the gap for domain-modeling.

Explicitly flag proposals that contradict an existing ADR.
